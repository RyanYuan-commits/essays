## 1 Reference: Rust 的安全指针

在 Rust 中, Reference 是最常用的指针, 它们是不拥有所有权的指针, 必须遵守以下核心的借用规则;

在任何给定的时间, 你只能拥有以下其中之一: 一个或多个不可变引用 `&T` / 一个可变引用 `&mut T`;

```rust
let mut data = String::from("Rust"); // data 拥有所有权

let r1 = &data; // 不可变借用 1
let r2 = &data; // 不可变借用 2 (允许)

// let r3 = &mut data; // 错误！当存在不可变引用时，不能创建可变引用。

std::mem::drop(r1); // r1 不再使用，借用结束
let r3 = &mut data; // 现在允许创建可变引用
```

## 2 Smart Pointer: 拥有所有权的指针

智能指针是封装了额外功能(如自动内存管理, 引用计数) 的结构体, 它们 **拥有** 它们指向的数据;

### 2.1 `Box<T>` 堆分配

将数据存储在堆上, 但 `Box` 本身, 仍然位于栈上, Rust 的 Box 在离开作用域时会自动释放内存.

这种自动内存释放机制是 Rust 内存安全保证的核心. 它体现了 RAII (Resource Acquisition Is Initialization) 原则, 确保资源 (在此例中是堆内存) 在其拥有的 `Box` 离开作用域时立即且确定性地被清理. 这消除了手动内存管理中常见的错误, 如内存泄漏和二次释放, 极大地提升了程序的可靠性.

因此, `Box` 主要用于将数据放置在堆上, 当栈空间不足以容纳大型数据结构时尤为重要, 或者在处理递归类型和特质对象时, 其大小在编译时无法确定. 它在栈上提供了一个稳定, 固定大小的指针, 用以管理堆上可能变长的分配, 使其成为 Rust 中灵活且安全的内存管理的关键工具.

### 2.2 `Rc<T>` / `Arc<T>`: 引用计数

Rust 的所有权系统在编译时强制执行严格的规则, 以确保内存安全. 然而, 在某些场景下, 例如图数据结构, 多层级配置共享或父子节点引用, 单个所有者模型会变得不便. 此时, `Rc` 和 `Arc` 提供了一种解决方案, 允许数据在不违反所有权规则的前提下被多个部分安全地引用和共享, 从而避免了不必要的数据复制和复杂的生命周期管理.

允许多个所有者共享堆上的数据, 只有当所有的 `Rc` 克隆体都销毁时, 数据才会被释放; `Rc` 用于单线程共享, `Arc` (Atomic Reference Count) 用于多线程共享, 是线程安全的.

尽管 `Rc` 和 `Arc` 解决了共享所有权的问题, 但它们本身并不提供内部可变性. 若要在共享数据被多个所有者持有的同时进行修改, 通常需要结合其他类型, 如 `Rc<RefCell<T>>` 用于单线程可变性, 或 `Arc<Mutex<T>>` (或 `Arc<RwLock<T>>`) 用于多线程安全的可变性. 

值得注意的是, 引用计数引入了运行时代价, 因为每次克隆或丢弃都会进行计数操作, 并且数据释放的时机取决于最后一个引用被销毁, 而不是编译时确定的. 

## 3 Rust 裸指针

Rust以其严格的内存安全保证而闻名, 但它也提供了一扇通往底层操作的“后门”, 即裸指针 (raw pointers). 

裸指针是 Rust `unsafe` 代码块中的核心组成部分, 主要用于与 C/C++ 等语言进行外部函数接口(FFI)交互、实现自定义内存分配器、或者构建需要绕过Rust所有权系统限制的复杂数据结构. Rust提供了两种类型的裸指针：`*const T` 用于不可变数据, 而 `*mut T` 用于可变数据. 

值得注意的是, 对裸指针的解引用操作必须封装在 `unsafe` 代码块内, 这明确地将内存安全责任转移给了开发者.

与Rust安全的引用（`&T`和`&mut T`）不同, 裸指针不具备任何所有权、生命周期或空值安全性保证. 它们可以指向任意内存地址, 甚至是非法的或未初始化的内存, 并且编译器不会对其进行任何运行时检查. 

这意味着使用裸指针时, 开发者必须手动确保其指向的内存是有效的、已正确分配且未被释放的. 因此, 裸指针是Rust提供给高级用户的强大工具, 允许他们在必要时放弃部分安全保证以换取极致的灵活性和对底层资源的精细控制, 但这也伴随着显著的风险和更高的编程责任.
