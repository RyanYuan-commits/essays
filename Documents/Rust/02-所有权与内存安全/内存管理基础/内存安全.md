`Wikipedia` 这样定义内存安全:

Memory safety is the state of being protected from various software bugs and security vulnerabilities when dealing with memory access，such as buffer overflows and dangling pointers.

常见的 "内存不安全" 的案例有:

- **空指针**: 解引用空指针是不安全的, 这块地址空间一般是受保护的, 对空指针解引用在大部分平台上会产生 segfault;
- **野指针**: 指未初始化的指针, 它的值取决于它的这个位置以前遗留下来的值是什么, 对野指针操作是不符合预期的;
- **悬空指针**: 内存空间在被释放之后继续使用, 跟野指针类似, 同样会读写已经不属于这个指针的问题;
- **使用未初始化的内存**: 任何一种类型不初始化直接使用是危险的;
- **非法释放**: 内存的分配和释放必须要配对, 对同一个指针释放两次, 会制造出内存错误;
- **缓冲区溢出**: 指针访问越界, 类似野指针, 会读取或修改临近内存空间的值;
- **执行非法函数指针**: 如果一个函数指针不是准确的指向一个函数地址, 那么调用这个函数指针会导致一段随机数据被当成函数来执行;
- **数据竞争**: 在有并发的场景下, 针对同一块内存同时读写, 且没有同步措施.

以上的问题是极度危险的, 并且它们的不一定在发生的时候触发 core dump, 而可能会导致程序一直 "带病" 运行, 而且因为原因与真正的表现之间并没有肉眼可见的关联, 最终导致极其隐蔽且难以排查的 bug.

在 Rust 语境中, 有一些内存错误是不在内存安全的范畴的, 比如内存泄漏和内存耗尽.

另外, panic 也不属于内存安全相关的问题, panic 和 core dump 之间有重要的区别, panic 是发生不可恢复错误后, 程序主动执行的一种错误处理机制, 而 core dump 则是程序失控后, 触发操作系统的保护机制而被动退出的.
