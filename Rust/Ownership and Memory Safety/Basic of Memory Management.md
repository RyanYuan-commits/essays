## 1	Heap and Stack

### 1.1	Stack

当一个函数被调用的时候, 系统会为它在当前线程的栈上创建一个栈帧, 并将其推入栈中, 栈帧中包含了改函数执行时需要的所有临时数据和控制信息; 一个典型的栈帧通常包含以下内容:

- **局部变量**: 所有在函数内部声明的, 编时已知大小的变量;
- **函数参数**: 调用函数时传递给函数的所有参数;
- **返回地址**: 函数执行完成后, 程序应该跳会到代码中的哪个位置;
- **其他控制信息**

Rust 栈帧中存储的数据大小是已知的, 所以只需要根据编译时推算出的大小移动栈指针就可以实现内存的分配和释放; 对于存储在堆上的数据, 栈上会存储一个指向堆数据的指针和一些元数据.

### 1.2	Heap

Rust 在堆上存储动态的, 可变大小的数据, 堆上数据的内存在运行时分配, 存储大小在编译时无法确定或者需要动态收缩的数据,  比如 `String`, ` Vec<T>` 等; 

相比于 Stack, 堆内存的分配和回收较慢, 因为它需要系统查找一块足够大的区域来存储数据, 堆内存释放由所有权机制自动管理, 当栈上的所有者变量超出作用域时, Rust 会通过 `Drop` trait 自动清理并释放堆上的内存.

## 2	Segfaults

Rust 官方网站给自己的介绍是: Rust is a systems programming language that runs blazingly fast, **prevents segfaults**, and guarantees thread safety.

segfault 实际上是 segmentation fault 的缩写, 可以翻译为段错误, segfault 是这样形成的: 

- 进程空间中每个段通过硬件 MMU 映射到真正的物理空间;
- 在这个映射中, 我们还可以给不同的段设置不同的访问权限, 比如代码段就是只能读不能写;
- 进程在执行这个的过程中, 如果违反了这些权限, CPU 会直接产生一个硬件异常;
- 硬件异常被操作系统内核处理, 内核会向进程发送一条信号;
	- 如果应用没有实现信号处理函数, 默认情况下, 这个进程会直接正常退出
	- 如果操作系统打开了 core dump 功能, 在进程退出的时候操作系统会把当时的内存状态, 寄存器状态, 以及各种相关信息保存下来;

在传统系统级编程语言 C/C++ 中, 制造 segfault 是很容易的, 程序员要非常小心才能避免这种错误;另一类规避 segfault 的语言, 使用的是自动内存回收机制, 在这些编程语言中, 指针的能力被大幅度限制, 内存被放在一个运行时环境中严格管理; Rush 主要设计目标之一就是在不用自动垃圾回收机制的前提下, 避免产生 segfault.

## 3	Memory Safety

`Wikipedia` 这样定义内存安全:

```
Memory safety is the state of being protected from various software bugs and security vulnerabilities when dealing with memory access，such as buffer overflows and dangling pointers.
```

常见的 "内存不安全" 的案例有:

- **空指针**: 解引用空指针是不安全的, 这块地址空间一般是受保护的, 对空指针解引用在大部分平台上会产生 segfault;
- **野指针**: 指未初始化的指针, 它的值取决于它的这个位置以前遗留下来的值是什么, 对野指针操作是不符合预期的;
- **悬空指针**: 内存空间在被释放之后继续使用, 跟野指针类似, 同样会读写已经不属于这个指针的问题;
- **使用未初始化的内存**: 任何一种类型不初始化直接使用是危险的;
- **非法释放**: 内存的分配和释放必须要配对, 对同一个指针释放两次, 会制造出内存错误;
- **缓冲区溢出**: 指针访问越界, 类似野指针, 会读取或修改临近内存空间的值;
- **执行非法函数指针**: 如果一个函数指针不是准确的指向一个函数地址, 那么调用这个函数指针会导致一段随机数据被当成函数来执行;
- **数据竞争**: 在有并发的场景下, 针对同一块内存同时读写, 且没有同步措施.

以上的问题是极度危险的, 并且它们的不一定在发生的时候触发 core dump, 而可能会导致程序一直 "带病" 运行, 而且因为原因与真正的表现之间并没有肉眼可见的关联, 最终导致极其隐蔽且难以排查的 bug.

在 Rust 语境中, 有一些内存错误是不在内存安全的范畴的, 比如内存泄漏和内存耗尽. 另外, panic 也不属于内存安全相关的问题, panic 和 core dump 之间有重要的区别, panic 是发生不可恢复错误后, 程序主动执行的一种错误处理机制, 而 core dump 则是程序失控后, 触发操作系统的保护机制而被动退出的.
