## 1	The Why

闭包的诞生, 是为了解决 "灵活性" 和 "上下文" 这两个核心问题.

- **灵活性**: 当应付一些重复书写的简单逻辑的时候, 我们不希望每次都去创建一个函数, 而是需要轻量级的, 随用随抛的匿名函数; 并且可以将其当做一个 Action 传递给另一个函数;
- **上下文**: 当我们将一个函数作为 Action 传递的时候, 可能同时也需要将当前的一些 "上下文" 也传递过去, 也就是需要这个匿名函数能够智能的捕获并使用它定义的环境中的变量.

因此, 闭包的本质就是: **一个可以捕获其环境的匿名函数**, 是 Rust 实现 Functional Programming 的重要工具.

## 2	Core Component

### 2.1	The Syntax

闭包使用 `|...| { ... }` 语法, 如果函数体只有一行表达式, 大括号可以省略;

- `|param1, param2|`: 两条竖线中间的是参数列表, 由这个 Closure 的使用者来传递;
	
- `{ ... }`: 闭包执行的逻辑, 有一个返回值 (默认 unit) 提供给调用者使用.

### 2.2	The Environment

```rust
let numbers = [5, 10, 15, 20, 25];
    let threshold = 10;

    let above_threshold: Vec<i32> = numbers
        .iter()
        .filter(|&num| *num > threshold)
        .map(|&num| num * 2)
        .collect();
```

闭包可以访问当前定义环境中的变量, 比如上面的案例中, 闭包捕获了 `threshold` 变量.

### 2.3	Fn Traits

是闭包的 "类型", 闭包如何捕获环境, 决定了它实现了那种 Trait, 编译器会自动为你推断:

- `FnOnce`: 通过 Move 语义来捕获变量, 它只能被调用一次, 因为它会消耗掉它捕获的变量;
	
- `FnMut`: 通过可变借用来捕获变量, 可以被调用多次, 并且在调用过程中可以修改环境中的变量;
	
- `Fn`: 通过不可变借用的方式来捕获变量, 它可以被调用多次, 但只能读取环境中的变量.

## 3	Mechanism

闭包的运作机制就是 Environment Capture, 当定义一个闭包的时候, Rust 编译器会检查这个 Closure 的函数体, 看它如何使用外部变量, 然后选取限制最少的捕获方式:

- 如果闭包只需要读取外部变量 (如 `println!("{}", my_var)`), 编译器会使用 Fn (不可变借用);
	
- 如果闭包需要修改外部变量 (如 `my_var += 1`), 编译器会使用 FnMut (可变借用);
	
- 如果闭包需要拿走外部变量的所有权 (如 `drop(my_var)`) , 编译器会使用 FnOnce (获取所有权).

也可以使用 `move` 关键字来_强制_闭包获取所有权, 无论它是否需要. 这在多线程编程中至关重要, 可以防止在不同线程间共享引用.

## 4	Boundaries

### 4.1	When to Use

**迭代器 (Iterators)**: 闭包的"主场"! 几乎所有的迭代器方法, 如 `.map()`, `.filter()`, `.find()`, `.fold()`, 都需要一个闭包作为参数.

**排序**: `Vec::sort_by()` 或 `sort_by_key()` 需要一个闭包来定义比较逻辑.

**多线程**: `std::thread::spawn()` 接收一个闭包. 你通常会用 `move` 闭包来把数据的所有权转移到新线程.
 
**事件处理/回调**: 在 GUI 编程或异步编程中, 用于定义"当...发生时, 执行..."的逻辑.

### 4.2	When Not to Use

当逻辑非常复杂, 或者需要在**多个完全不同**的地方复用时, 把它定义为一个具名的 `fn` 函数通常更清晰.

当你需要一个"函数指针" (function pointer) 时. 闭包不是函数指针, 尽管不捕获环境的闭包可以被_强制转换_为函数指针.
